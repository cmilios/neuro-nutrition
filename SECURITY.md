# Security policy

## Report vulnerabilities privately

Use GitHub's
[private vulnerability-reporting form](https://github.com/cmilios/neuro-nutrition/security/advisories/new)
for suspected vulnerabilities in NeuroNutrition. Private reporting is enabled
for this repository. Do not open a public issue for a vulnerability or include
exploit details in a public discussion.

Include only the information needed to investigate:

- the affected application surface or repository component;
- the security impact and conditions required to reproduce it;
- a minimal, sanitized reproduction or proof of concept; and
- any suggested mitigation, if known.

Do not include real account credentials, session or recovery links, tokens,
authorization codes, secret values, email addresses, Health Profile data,
private Weekly Plans, raw provider responses, or another person's information.
Use synthetic placeholders and redact screenshots and logs. If sensitive
material is essential to triage, first ask through the private report how to
transfer it safely.

Maintainers will acknowledge and triage reports through the private advisory.
The project does not currently promise a response or remediation deadline.
Please allow maintainers to coordinate a fix and disclosure before publishing
details.

For ordinary bugs or documentation problems with no security impact, use the
[public issue tracker](https://github.com/cmilios/neuro-nutrition/issues) after
removing personal and sensitive information.

See [Privacy and security: current technical boundaries](docs/privacy-and-security.md)
for the current data inventory, trust boundaries, telemetry exclusions, and
deletion limitations.
